# What PR #311 could break

**fix: use PUT method for article updates in editor** · [https://github.com/realworld-apps/angular-realworld-example-app/pull/311](https://github.com/realworld-apps/angular-realworld-example-app/pull/311)

> Editing an article now saves with an update call (PUT) instead of a create call. The Publish Article button on the editor page is affected, and the edit path was never seen in the running app.

## Re-test first

1. Open the editor page at /editor, fill in a new article and click Publish Article. This was seen in the running app. It still creates the article through the create call. *(High confidence)*
2. Open an existing article in the editor and click Publish Article. The change says this should now send an update (PUT). This path was never seen in the running app, so check it by hand. It needs an article owner login. *(Medium confidence, not seen in the app)*
3. Check that editing an existing article does not create a duplicate. The code also shows a create call from the edit page. It was never seen in the running app. *(Medium confidence, not seen in the app)*

## What changed for users

- The Publish Article button on the editor page is changed by this PR. Every screen element that proves the button requirement is changed. Its existing coverage is lost until you re-check it. *(High confidence)*
- The editor page for creating and editing articles is affected. It is available at /editor and /editor/article-slug-here. *(High confidence)*

## Seen in the running app

- The Publish Article flow on /editor was seen in the running app. It ends in a create call. *(High confidence)*
- The route /editor, which shows New article, was seen in the running app. *(Medium confidence)*

## Never seen in the running app

- The update call for articles was never seen in the running app. It is only in the code. No crawled button triggered it. *(Medium confidence, not seen in the app)*
- The route /editor/:slug, which shows Edit article, was never seen in the running app. *(Medium confidence, not seen in the app)*
- Publish Article on the edit page, from code only, was never seen. Both the create and the update versions are in this group. *(Medium confidence, not seen in the app)*

## Coverage gaps

- The update call requirement has no UI coverage to re-check it with. It needs an owner login state that the crawl did not have. *(Medium confidence, not seen in the app)*
- The Publish Article button requirement loses its coverage because every element that proves it changed. *(High confidence)*
