# What PR #311 could break

**fix: use PUT method for article updates in editor** · [https://github.com/realworld-apps/angular-realworld-example-app/pull/311](https://github.com/realworld-apps/angular-realworld-example-app/pull/311)

> Editing an article now saves with a PUT instead of a POST, so re-test saving edits first and check that creating a new article still works.

## Re-test first

1. Edit your own published article and save it with the Publish Article button. This is the core of the fix. The edit should now go out as a PUT. *(High confidence)*
2. Check the Publish Article button on the editor page for an existing article. It now takes the new update path. *(High confidence)*
3. Check the editor page for editing an article at the edit address. Its save behaviour is what changed. The page display itself did not. *(High confidence)*
4. Publish a new article as a regression check. The create path is meant to be unchanged, but the shared save code was restructured. *(Medium confidence)*
5. Delete your own article. This is a low-priority check. The editor is only used to set up the article, and the delete action is not touched. *(Medium confidence)*
6. Open the New article page. Only a light check is needed. It is affected only through the unchanged create path. *(Low confidence)*

## What the change does

- The editor's save code now reads the article slug from the page address. On the edit page it sends an update as a PUT. Otherwise it creates the article with a POST. Before, it always sent a POST, so edits went out as POSTs. The create path is unchanged. *(High confidence)*

## Coverage at risk

- Existing checks for the Publish Article button on the editor page may no longer prove it. Every element that proves it is changed by this PR. *(High confidence)*
- Existing checks for the app calling PUT on an article may no longer prove it. Every element that proves it is changed by this PR. *(High confidence)*
