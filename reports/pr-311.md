# What PR #311 could break

**fix: use PUT method for article updates in editor** · [https://github.com/realworld-apps/angular-realworld-example-app/pull/311](https://github.com/realworld-apps/angular-realworld-example-app/pull/311)

> Editing an article now saves with an update request (PUT) instead of a create request. Creating a new article is unchanged.

## Re-test first

1. Save an edited article and confirm the app sends an update request (PUT) for that article. This is the fix itself. *(High confidence)*
2. Open the Edit article page at /editor/:slug. This is where the behaviour changed. *(High confidence)*
3. Check the editor page for creating and editing articles, at /editor and /editor/article-slug-here. *(High confidence)*
4. Click the Publish Article button on the editor page. On an existing article it now updates. On a new article it still creates. *(High confidence)*
5. Run the flow 'Edit your published article'. It uses exactly the new update path. *(High confidence)*
6. Run the flow 'Publish a new article' as a regression check. The create path was only refactored. *(Medium confidence)*
7. Re-run these edit tests: 'should edit an existing article', 'should remove all tags when editing an article', 'should handle 403 when updating article' and 'should show error message on update article form when network fails'. They all use the Publish Article button on the edit page. *(High confidence)*
8. Re-run 'should create a new article' as a regression check on the shared, refactored code. *(Medium confidence)*

## What the change does

- The editor now checks whether the page address has an article slug. With a slug (/editor/:slug), it updates the article with PUT. Without one (/editor), it creates the article with POST. Before, editing sent a create request. *(High confidence)*

## Coverage at risk

- The Publish Article button has no trusted test coverage until its tests are re-run and pass. All 28 tests that check it go through changed UI. *(High confidence)*
- The PUT update call has no trusted coverage either. All 5 tests that check it go through changed UI. *(High confidence)*
