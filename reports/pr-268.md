# What PR #268 could break

**# New Article page fixes** · [https://github.com/realworld-apps/angular-realworld-example-app/pull/268](https://github.com/realworld-apps/angular-realworld-example-app/pull/268)

> The New Article page no longer loads an article or runs the author check when there is no slug. Separately, the show-when-logged-in behaviour changed and may not re-show content after a logout and login.

## Re-test first

1. New article page at /editor: it should open with no article lookup and no author-check redirect. The edit path with a slug is meant to be unchanged. *(High confidence)*
2. Editor page fields and button: the title, description, body and 'Enter tags' fields and the Publish Article button. Until the tests that check them pass again, they have no trusted coverage. *(High confidence)*
3. Flow 'Publish a new article': it is exactly the changed branch. *(High confidence)*
4. Flow 'Edit your published article': the edit path is unchanged, but the flow first creates the article on /editor. *(High confidence)*
5. Flows 'Delete your own article' and 'Favorite your own published article'. Both pass through changed UI. *(High confidence)*
6. Tests that create an article with the Publish Article button on /editor: should create a new article; should only allow author to edit/delete article; should handle 400 on article creation; should show error message on create article form when network fails; newly registered user should show default avatar in comment section; newly registered user should show default avatar on article meta; page should reset when switching feeds; pagination should update URL with ?page=N; pagination should work with /tag/:tag; should delete an article when server returns 200 instead of 204; should display article preview correctly; should display popular tags; should display user articles on profile; should filter articles by tag; should load correct page when navigating directly to ?page=N; should navigate to article from author name; should paginate articles; should show article count on profile tabs; should switch between Global Feed and Your Feed; should view article from home feed; should view own profile; tag pagination shows correct articles per page. *(High confidence)*
7. Tests that use the Publish Article button on the edit page /editor/:slug: should edit an existing article (it also creates an article on /editor first); should remove all tags when editing an article; should unfavorite an article. *(High confidence)*
8. Test 'should require login to post comment': it checks the comment box for logged-out versus logged-in users, which depends on the changed show-when-logged-in behaviour. *(High confidence)*

## Editor page controls affected

- On /editor (new article), these were all seen in the running app: the Article Title, description, body and 'Enter tags' fields, and the Publish Article button. *(High confidence)*
- The same controls on /editor/:slug (edit your own article) were also seen. The edit path is unchanged, but the page setup now goes through the new slug condition. *(High confidence)*

## Logout and login risk

- The show-when-logged-in behaviour now builds its content only once. It is never cleared afterwards. After a logout and then a login in one session, logged-in content may not show again. Logged-out-only content may not return after a login and then a logout. Try both sequences by hand. *(High confidence)*

## Never seen in the running app

- Three items were found only in code, never in the running app. All have low confidence (0.32): the 'Realworld' link and the demo text on the home page, and the 'or to add comments on this article.' text on the article page. *(Low confidence, not seen in the app)*
